## ADDED Requirements

### Requirement: Report page wraps Firebase read in SWR
`app/(public)/assessment/analysis/page.tsx` SHALL wrap the Firebase Realtime DB read (`get(ref(database, 'assessments/{leadId}/{id}'))`) in a `useSWR` call keyed by `['assessment-submissions', leadId, assessmentId]`. Bare `useEffect`+`useState` for data loading SHALL be removed. All locally defined interfaces duplicating submission shape SHALL be replaced with typed local interfaces only where SDK types do not cover Firebase-specific data (Firebase submission records are not in the Strapi SDK).

#### Scenario: Submissions load and render
- **WHEN** the user navigates to `/assessment/analysis?id=<id>` and Firebase has submission records
- **THEN** SWR fetches the Firebase snapshot and renders a list of submission cards sorted newest-first

#### Scenario: Loading skeleton shown while fetching
- **WHEN** SWR is in the loading state
- **THEN** three skeleton cards render as placeholders

#### Scenario: Empty state shown when no submissions
- **WHEN** Firebase has no records for this assessment and user
- **THEN** the "No submissions yet" empty state renders with a "Take Assessment" CTA

### Requirement: Report page UI matches reference design
The report page SHALL render matching `AssessmentReport.png`: a header "Assessment Report", an "AI-generated summary" badge, an overall balance/score line, a prose summary section, and a prominent orange "Book appointment with a specialist" CTA button at the bottom. The summary text SHALL be derived from the most recent submission's answer data (score-based interpretation). A disclaimer line ("This summary is generated by AI…") SHALL appear below the CTA.

#### Scenario: Report renders with most recent submission data
- **WHEN** two submissions exist
- **THEN** the report displays score/summary derived from the most recent (newest) submission

#### Scenario: Book appointment CTA navigates to appointments
- **WHEN** the user taps "Book appointment with a specialist"
- **THEN** the router pushes to `/appointments`

### Requirement: SDK types replace manual type declarations
All files in the assessment feature that declare local interfaces shadowing Strapi API response shapes SHALL remove those local interfaces and import the equivalent types from `sdk/strapi/types.gen.ts`. Where SDK types are more permissive (e.g. `unknown` fields), a narrow adapter/mapper function SHALL be used at the boundary rather than duplicating the full type locally.

#### Scenario: No duplicate interface declarations after migration
- **WHEN** `tsc --noEmit` runs post-migration
- **THEN** no assessment page file contains a locally defined interface whose fields duplicate a type exported from `sdk/strapi/types.gen.ts`

### Requirement: Dead assessment pages are deleted
The following files SHALL be deleted as they are superseded or unreachable after route consolidation:
- `app/(public)/assessment/page.tsx` (redirect-only page)
- `app/(public)/assessment/form/page.tsx` (replaced by `[id]/page.tsx`)
- `app/(auth)/assessments/[slug]/page.tsx` (replaced by details + form routes)
- `app/(auth)/assessments/[slug]/questions/page.tsx` (if it exists and is dead)
- `app/(auth)/stress-management/assessment/page.tsx` (dead — stress-management route is deleted per git status)
- `app/(auth)/assessments/constants.ts` (static data replaced by API)

#### Scenario: Build passes after dead file deletion
- **WHEN** all listed dead files are deleted
- **THEN** `next build` completes without errors referencing the deleted paths
