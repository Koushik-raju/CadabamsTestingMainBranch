# SDK Migration Report
**Date:** 2026-04-07  
**Scope:** Replace all legacy CRM/backend direct calls with `sdk/auth-and-crm/` SDK calls

---

## Summary

The app had two parallel systems for backend communication:
- **SDK** (`sdk/auth-and-crm/`) — canonical system using Bearer token auth, generated by `@hey-api/openapi-ts`
- **Legacy services** (`services/`) — axios clients using OAuth 1.0 signatures, pointing to a different CRM system

This migration removes all legacy service usage that had SDK equivalents and deletes the now-unused service files.

## What Was NOT Replaced (and Why)

### Auth Route Handlers — KEPT
Files in `app/api/auth/` (send-otp, verify-login, signup/verify, logout, refresh, me) **must remain**. Although they internally call the SDK, they serve a critical purpose: setting **HTTP-only cookies** for `access_token` and `refresh_token`. This can only be done server-side in Next.js route handlers. Client code cannot set httpOnly cookies directly.

### Service Files — KEPT

| File | Reason SDK Cannot Replace |
|------|--------------------------|
| `services/prescription.service.ts` | Calls hospital CRM (`hosClient` OAuth 1.0) — no `/prescriptions` endpoint in SDK |
| `services/leaderboard.service.ts` | Calls general backend — no `/leaderboard` endpoint in SDK |
| `services/assessment.service.ts` | Assigned assessments/worksheets — no SDK equivalent |

### External APIs — KEPT (Third-party, out of scope)

## Key Technical Notes

### Payment URL Shape Change
Legacy services extracted `response.data.result.short_url` (nested CRM shape).  
SDK `postPaymentsPackage` / `postPaymentsAppointment` returns flat `{ redirect_url }`.  
All payment call sites now use `res.data?.redirect_url` directly.

### SDK Error Handling
SDK functions never throw — errors land in `res.error`. All write operations now check:
```ts
if (res.error) throw new Error(JSON.stringify(res.error));
```

### Package Filter Migration
Legacy code passed Odoo domain filter string: `[["service_id", "in", [1,2,3]]]`  
SDK `getPackages` accepts comma-separated `service_ids` query param: `"1,2,3"`

### Type Casting Strategy
SDK `Package[]` and local `AvailablePackage[]` are structurally compatible (same fields, minus `journey_id`/`journey_document_id` which are absent in SDK). Cast used: `as unknown as AvailablePackage[]`. Same for `ManagedPackage[]` → `BookedPackage[]`.
